# Parcel Exception Triage

An LLM automation that reads inbound parcel-delivery **exception messages** (customer emails and carrier status notes, in **English and German**), classifies them, extracts the key fields, drafts a reply, escalates urgent cases to a human, and **measures its own impact**.

Classification runs on **Claude** via tool-use, with a transparent keyword baseline as a no-cost fallback. Structured output is guaranteed by the tool schema, a human stays in the loop, and every decision is measured.

## What it does

Each message goes in as text; a structured decision comes out:

```json
{
  "category": "damaged_parcel",
  "urgency": "high",
  "tracking_id": "DHL772100544",
  "order_id": null,
  "needs_customer_reply": true,
  "suggested_reply": "Es tut uns leid, dass Ihr Paket beschädigt ankam ..."
}
```

Categories: `delayed`, `failed_delivery_attempt`, `damaged_parcel`, `customs_hold`, `address_issue`, `lost_parcel`, `delivered_not_received`, `return_to_sender`.

## Architecture
generate_data.py ──► data/exceptions*.jsonl
│
message ─► classifier.py ─► schema.py (tool-use schema contract)
│
├─ triage.py classify a whole dataset ─► results.jsonl
├─ workflow.py agentic steps: classify → validate → route → hand off
├─ service.py FastAPI POST /triage (callable by Make.com etc.)
└─ batch.py Message Batches API for high volume
│
results ─► evaluate.py headline metrics (volume, accuracy, time saved)
├─ report.py precision / recall / F1 + confusion matrix
└─ dashboard.py self-contained HTML dispatch console

## Quick start

```bash
# Offline baseline — no key, no dependencies, runs immediately:
python src/triage.py && python src/evaluate.py
```

### Run on Claude

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...      # console.anthropic.com
python src/check_api.py                  # verify the key works
python src/triage.py && python src/evaluate.py
```

### Deeper metrics, dashboard, service, tests

```bash
python src/generate_data.py 300              # scale the eval set
python src/report.py                         # precision / recall / F1 + confusion matrix
python src/dashboard.py                      # writes dashboard.html
uvicorn service:app --reload --app-dir src   # live API at http://127.0.0.1:8000/docs
pytest -q
```

## Results

Measured on a 36-message evaluation set:

| Metric | Value |
|---|---|
| Messages handled | 36 |
| Category accuracy | 94% |
| Est. manual effort saved | ~96 min (~2.7 min/msg) |

The two remaining misses are genuinely ambiguous, multi-signal messages (a return-to-sender that also mentions a failed delivery; an address problem phrased like a lost parcel) — kept as an honest error-analysis backlog.

## Design decisions

- **Reliable structured output** — the classification schema is passed to the model as a tool, so the result is always a valid object rather than free text that has to be parsed.
- **Human in the loop** — replies are *drafted*, never auto-sent, and high-urgency cases are escalated to a person. The system supports operators; it doesn't replace their judgement.
- **Measured** — volume handled, accuracy/error rate, and time saved are tracked and visualised, not assumed.
- **Pluggable backend** — Claude and a rule baseline sit behind one interface, so the pipeline is free to develop and it's easy to measure what the LLM adds over rules.
